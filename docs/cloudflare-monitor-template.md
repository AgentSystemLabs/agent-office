## M1 Requirements and architecture

An Office-owned timer discovers current zones, web DNS names, Worker domain bindings, route mappings, Worker scripts and Pages using the designated removable-drive Cloudflare credential file. The path is local configuration; the token is read only in server memory, never copied into configuration, logs, CLI arguments, browser state or repository. Only GET metadata and a fixed read-only GraphQL analytics query are permitted. No production resource/configuration mutations, deployment, server monitor, cron, or Tail Worker installation.

Every 60 seconds Office independently probes discovered public HTTPS website roots, with bounded concurrency, DNS/IP checks, certificate validation, response limits and an overall deadline. Local/private IPs, credentials in URLs, alternate protocols and arbitrary caller URLs are rejected. Redirects are reported without following unverified targets. Do not mistake Access/challenge/auth, redirects, zero traffic, stale observations or missing API permissions for complete application health.

Refresh discovery and the last-15-minute Worker aggregate requests/errors/outcomes every five minutes. Preserve observation timestamps, capability failures and incomplete pagination. Pages/API permission errors remain visible. Only latest observations generated by this monitor may be persisted; they are explicitly stale on reload until refreshed. Never seed from earlier inventory files. Bound all arrays and persisted history. Do not collect raw HTTP bodies or console logs into persistent state. Initially show error classes/outcomes/counts; unavailable detailed application logs must be explicit.

## M2 Interfaces and UX

Local `.agent-office/cloudflare-monitor.json` contains only `credentialFile` and `enabled`. No unauthenticated monitoring results or configuration API. A signed-in GET `/api/domain-monitor` returns sanitized current state. Start/stop through Office timer lifecycle, not panel visibility or an agent's task. The Services window exposes Cloudflare monitoring, and the menu offers a direct Cloudflare status action. Show monitor location, time of last/next check, per-domain HTTPS status/latency/error/ray ID, Worker mapping and aggregate error outcomes, capability errors, and stale/closed-Office limitations. Close button and Esc retain Office focus behavior. 2D Services should expose the same monitoring panel.
